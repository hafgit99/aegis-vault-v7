# Aegis Vault 7 - Security Audit Package

This directory contains key documentation and configuration artifacts prepared for third-party security audits. Aegis Vault 7 implements a local-first, zero-materialization security architecture designed to prevent the exposure of master credentials in runtime memory or application logs.

## Package Integrity (SHA256SUMS.txt)

This package ships a `SHA256SUMS.txt` manifest so a third-party auditor can prove the delivered documents were not modified in transit or after hand-off.

- The manifest is generated by `scripts/generate-audit-package-checksums.cjs` and contains one `<sha256>  <relative-path>` line per file in this directory, sorted alphabetically and using forward-slash relative paths so it is portable across Linux, macOS, and Windows auditors.
- The manifest itself is excluded from hashing so regeneration stays idempotent and non-circular.
- Generation prints provenance metadata to the console only (package version, git commit/branch, clean-tree status, UTC timestamp, file count, and the SHA-256 fingerprint of the manifest). The release owner should record that metadata alongside the hand-off; it is intentionally not written into the manifest so the file stays a pure `sha256sum -c` artifact.

### Generating

```bash
npm run audit:checksums
```

### Verifying

Coreutils (recommended for the auditor):

```bash
cd SECURITY_AUDIT_PACKAGE && sha256sum -c SHA256SUMS.txt
```

Node-based (no coreutils required):

```bash
npm run audit:checksums:verify
```

Both exit non-zero on any missing file or hash mismatch. If the auditor requires a detached PGP signature over `SHA256SUMS.txt`, the release owner should generate and deliver it alongside the package; signature creation is intentionally out of scope for the generator script.

## Key Control: No-JS-Master-String Final Gate

To guarantee that the plain-text master password string does not materialize during routine application flows (CRUD, settings panel dashboard, or attachment retrieval), Aegis Vault 7 uses an automated gate:

- **Scan Target**: Recursively scans all source files (`.ts`, `.tsx`, `.js`, `.jsx`) in the `src/` directory.
- **Forbidden Patterns**:
  - `withActiveMasterPassword`
  - `getActiveMasterPassword`
  - `masterPasswordPlain`
  - `passwordPlain`
  - `deriveEncryptionKey`
- **Allowlist Enforced**: Only specific, authorized boundaries (setup, password rotation, migration, and test suites) are allowlisted.
- **Strict Occurrence Bounds**: Every allowlisted file is restricted to an exact baseline count of occurrences. Any addition of master-string logic outside or exceeding these baselines triggers a build-time and test-time failure.

### Running the Scan

The security scan can be executed locally using the following command:

```bash
npm run security:no-js-master-string
```

It is also run automatically during unit tests:

```bash
npm run test:unit
```
