Projekt / Quellcode

Das Ganze liegt auf GitHub

KalderaShield ist unter Apache-2.0 lizenzierter Open Source: die Desktop-App, die Android-App, die Browser-Erweiterung, der nativeMessaging-Host und diese Website. Jede Sicherheitsaussage auf dieser Website lässt sich auf Code oder auf einen Test zurückführen, der in der öffentlichen CI läuft.

Repository öffnen Sicherheitsrichtlinie
Was die Codebasis ist

Vier Projekte, ein Repository

Die Desktop-Anwendung verbindet ein React- und TypeScript-Frontend über Tauri 2 mit einem Rust-Kern: Die Oberfläche rendert in der System-WebView, die native Seite übernimmt den Updater, die Erweiterungsbrücke und Plattformintegrationen. Die Tresor-Persistenz läuft auf wa-sqlite mit einem versionierten Schema-Umschlag.

Die Browser-Erweiterung ist ein Manifest-V3-TypeScript-Build für Chromium und Firefox, und die Android-App ist ein Tauri-Android-Projekt mit AndroidKeyStore-Biometrie-Bindung. Der nativeMessaging-Host und die IPC-Brücke liegen im Rust-Workspace, wo sich Kopplungstoken, Lease und Frame-Verschlüsselungslogik am leichtesten prüfen lassen.

Die Website selbst ist schlicht eingechecktes HTML — kein Build-Schritt für die Auslieferung — mit Generatorskripten und Quality-Gates, die neben den Seiten liegen, die sie erzeugen.

Die Gates, die jede Änderung durchläuft

Typprüfung und 2204 Unit-Tests

248 Testdateien mit erzwungenen Abdeckungsschwellen: 90 % Zeilen, 90 % Anweisungen, 85 % Funktionen, 80 % Zweige. Eine Regression unter der Schwelle lässt den Build fehlschlagen, nicht ein Dashboard.

Fuzz-, Mutations- und Sicherheitsgates

fast-check-Eigenschaftstests bearbeiten Importer-, Sicherungs- und Anhangspfade mit fehlerhaften Eingaben. Stryker-Mutationstesting bewertet die Testqualität. Eigene Gates prüfen CSP-Härtung, Release-Artefakte, Debug-Marker und Geheimnisse.

Analyse der Lieferkette in der CI

CodeQL analysiert den Code, OpenSSF Scorecard bewertet die Sicherheit des Repositorys, gitleaks blockiert eingecheckte Geheimnisse, und die Abhängigkeitsrichtlinie schlägt bei jedem hohen oder kritischen Advisory fehl; für die übrigen gilt eine dokumentierte Akzeptanz.

Sicherheitsarchitektur

Was Open Source hier bedeutet — und was nicht

Eine Aussage mit ihrer Grenze

Open Source ermöglicht jedem, den Code zu lesen; es beweist nicht von selbst, dass jemand es getan hat. Das Lesen ist der ganze Sinn: Das Bedrohungsmodell, die Akzeptanzregister und der Auditumfang liegen im Repository, damit Prüfer von derselben Karte ausgehen. Ein unabhängiges Audit wurde nicht abgeschlossen — die Auditstatus-Seite sagt das direkt.

TypeScript

Frontend und Erweiterung

React-Oberfläche, Erweiterung und gemeinsame Tresorlogik, streng typisiert; keine React-Inline-Styles, erzwungen durch das CSP-Gate.

Rust

Nativer Kern

Tauri-2-Befehle, nativeMessaging-Host, Loopback-IPC-Brücke und Updater-Verdrahtung; cargo fmt und gezielte Tests für atomare Schreibvorgänge als Gate vor jeder Veröffentlichung.

Apache-2.0

Lizenz

Das gesamte Projekt plus eine THIRD-PARTY-Lizenzdatei für gebündelte Komponenten. Keine proprietären Blobs in den Installationsprogrammen.

Häufig gestellte Fragen

Beiträge und Meldungen

Wie melde ich eine Sicherheitslücke?

Privat, niemals als öffentliches Issue: über GitHub private vulnerability reporting oder die E-Mail in SECURITY.md. Bestätigung innerhalb von 48 Stunden, Triage innerhalb von 7 Tagen, koordinierte Offenlegung innerhalb von 90 Tagen.

Kann ich Code beisteuern?

Ja — über GitHub-Pull-Requests. Die oben beschriebenen Gates laufen bei jeder Änderung; der schnellste Weg zu helfen ist eine Änderung, die sie grün hält und eigene Tests mitbringt.

Kann ich die Installationsprogramme selbst bauen?

Ja. Der lokale Release-Leitfaden dokumentiert die genauen Befehle pro Plattform, und das Release-Skript sammelt Artefakte mit SHA-256-Prüfsummen unter release-local/<platform>/.
